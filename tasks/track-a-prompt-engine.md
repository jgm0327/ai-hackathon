# 2부 — 경력기술서 생성 (신규, P0)

## 목표
**한 프로젝트에 속한 카드들을 묶어 STAR 형식 경력기술서 항목으로 변환한다.**

단건 변환과 근본적으로 다른 작업이다. 여러 카드를 가로질러 읽고,
**시간이 떨어진 조치와 결과를 인과로 연결**해야 한다. 이것이 제품의 존재 이유다.

## 인터페이스 계약
```python
# src/parsing/resume.py
from dataclasses import dataclass

@dataclass
class StarItem:
    title: str               # "결제 API 성능 개선"
    period: str              # "2023.02 - 2023.03"
    situation: str

    action: str
    result: str              # 숫자가 없으면 빈 문자열 — 절대 추정 금지
    source_dates: list[str]  # ["02.14", "02.17", "03.02"] — 근거 추적용, 생략 불가

def build_resume(cards: list[Card], jd_text: str | None = None) -> list[StarItem]:
    """한 프로젝트의 카드를 묶어 STAR 항목들로 변환한다.

    jd_text가 주어지면 해당 채용공고에 맞는 항목 위주로 재구성하고 순서를 조정한다.
    """
```

## 입력 포맷

카드 전체를 날짜순으로 정렬해 한 번에 넘긴다. **청킹이나 벡터 검색 불필요** —
카드 한 장이 100자 안팎이라 수십 장도 컨텍스트에 여유롭게 들어간다.

```
프로젝트: A은행 차세대 (2023.02 - 2023.11)

[02.14] 결제 API 느려서 레디스 캐시 붙임  #Redis #성능
[02.17] 쿠폰 중복 버그 잡아서 핫픽스 배포  #결제
[03.02] 레디스 붙인 뒤 결제 오류율 0.8% → 0.3%  #성능
[04.11] 정산 배치 8시간 걸리던 거 병렬로 돌림  #배치
[05.20] 정산 배치 8시간 → 1시간 20분  #배치
```

## 프롬프트 필수 제약 (CLAUDE.md 2.2)

아래 두 문장은 **반드시** 시스템 프롬프트에 포함한다.

```
같은 작업 흐름에 속하는 기록끼리 묶어라. 특히 조치를 취한 기록과 그 결과가
나중에 관측된 기록은 시간이 떨어져 있어도 하나로 묶어라.

결과에는 기록에 실제로 적힌 숫자만 써라. 숫자가 없으면 result를 빈 문자열로
남겨라. 추정하거나 지어내지 마라.
```

**환각 수치는 이 제품에서 가장 심각한 결함이다.** 유저가 면접에서 검증당한다.
