# 작업 로그 (logs/)

각 트랙(A~E)마다 하나의 누적 로그 파일을 둔다. **작업 세션이 끝날 때마다**
(하루 작업 끝, 또는 하나의 작업 항목을 완료했을 때) 해당 트랙 파일 맨 아래에
`TEMPLATE.md` 형식으로 새 항목을 추가한다.

## 파일 목록
- `track-a.md` — 프롬프트 엔지니어링
- `track-b.md` — 에이전트/MCP/벡터DB/노션 연동
- `track-c.md` — Streamlit 프론트엔드
- `track-d.md` — 배포
- `track-e.md` — 푸시 알림 (선택)

## 왜 남기나
1. **트러블슈팅 기록**: 같은 문제를 팀 내 다른 사람(에이전트)이 반복해서 겪지 않도록.
   특히 Track B의 Notion MCP, Track D의 배포 이슈처럼 리스크가 큰 구간은 기록이
   곧 다음 판단(폴백 여부)의 근거가 된다.
2. **회고/생각**: 왜 그 선택을 했는지, 뭘 다르게 했으면 좋았을지 — 이건 나중에
   `/areas/portfolio-materials.md`나 자소서/면접 답변으로 그대로 옮겨쓸 수 있는 재료다.
   이 프로젝트가 하는 일("낙서 → 정제된 경력기술서")을 팀 스스로도 실천하는 셈이다.

## 작성 원칙
- 코드 리뷰용 커밋 메시지가 아니라 **나중에 다시 읽었을 때 상황이 재구성되는 수준**으로 쓴다
  (예: "안 됨" 대신 "OOO 에러 발생, XXX가 원인으로 추정, YYY로 해결")
- 매일 다 채우지 않아도 된다. 트러블슈팅이 없었으면 생략 가능. 단, 리스크 구간
  (Notion MCP, Chroma 퍼시스턴스, PWA 푸시)은 진행 상황을 반드시 남긴다
  (`docs/03-risk-fallback.md`, `docs/04-push-notifications.md`의 타임박스 판단 근거가 됨)
