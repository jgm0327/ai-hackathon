# 아키텍처 개요 (2026-09-13 개정)

## 1. 전체 구성

```
[브라우저 — 폰 또는 데스크탑]
   Next.js: 화면 / 마이크 / PWA / 웹푸시 구독
        │  HTTPS
        ▼
[OCI VM]
   nginx  ┬─ /      → Next.js (localhost:3000)
          └─ /api/  → FastAPI (localhost:8000)
                        ├─ parsing.parser.parse_note()
                        ├─ parsing.resume.build_resume()   ★ 핵심
                        ├─ storage.db (SQLite)
                        ├─ agent.vectorstore (Chroma)
                        └─ agent.notion_client (REST, 읽기 전용)
```

---

## 2. 두 개의 흐름

이 제품에는 성격이 다른 두 경로가 있고, **비용 구조가 정반대**다.

### 2.1 매일 경로 — 가볍게

```
메모 한 줄 → parse_note() → save_card()
```

하루 1회, 3초 안에 끝나야 한다. LLM 호출 1번, 입력 200토큰 / 출력 150토큰.
**JD 매칭을 여기서 하지 않는다.** 이직 준비 때만 필요한 걸 매일 돌릴 이유가 없다.

### 2.2 이직 준비 경로 — 무겁게

```
프로젝트의 카드 전부 → build_resume(cards, jd_text) → STAR 항목들
```

한 달에 몇 번. LLM 호출 1번, 입력 2,500토큰 / 출력 2,000토큰.
**여기가 제품의 값어치 전부다.**

## 3. 왜 Streamlit을 걷어냈는가

**음성 입력 때문이다.** 자차 출퇴근자가 폰으로 말해서 기록하는 경로는 제품 컨셉의 절반이고,
노트북으로 대체가 안 된다.

Streamlit에서 마이크·PWA·푸시를 쓰려면 `st.components.v1.html`이 만드는 **샌드박스 iframe**
안에서 동작해야 한다. 여기서 세 가지가 막힌다.

| 항목 | 제약 |
|---|---|
| 마이크 권한 | iframe에 `allow="microphone"`이 내려와야 하는데 제어 불가 |
| 서비스워커 scope | `/app/static/` 하위로 제한. manifest의 `start_url: "/"`와 불일치 |
| manifest 주입 | `window.parent.document`로 부모 문서를 건드려야 함 |

기존 `install_button.py` 주석이 이 실패를 스스로 기록하고 있다.
Next.js에서는 페이지가 이 셋을 **직접 소유**하므로 문제가 통째로 사라진다.

부수 효과로 Figma 디자인(390px, 바텀시트, 하단 탭바, 칩, 스켈레톤)이 구현 가능해진다.

## 4. 데이터 계층

### 4.1 왜 SQLite인가
단일 VM, 단일 프로세스, 데이터 수천 건 규모. 별도 DB 서버를 띄울 이유가 없다.
OCI 블록 스토리지는 재시작에도 유지되므로 클라우드 DB 불필요.

### 4.2 프로젝트 층의 존재 이유
SI에서 A은행의 "결제 API 개선"과 B카드의 "결제 API 개선"은 문장이 거의 같지만
경력기술서에는 별개로 들어가야 한다. 섞이면 경력이 반으로 줄어든다.

**내용 유사도로는 이 구분이 원천적으로 불가능하다.** 실제로 비슷하기 때문이다.
그래서 바깥 상자는 유저가 지정하고(`is_current`), 새 카드는 자동 배정된다.

### 4.3 작업 묶음은 저장하지 않는다
같은 프로젝트 안에서 "레디스 도입"과 "오류율 개선"을 묶는 일은 `build_resume()` 호출
시점에 LLM이 그때그때 한다. DB에 저장하면 관리 UI가 필요해지고,
그 순간 "평소 입력 비용 0" 원칙이 깨진다.

## 5. 임베딩과 LLM의 역할 분담

| | 임베딩 | LLM |
|---|---|---|
| 질문 | 이 둘이 **비슷한가** | 이 둘이 **이어지는가** |
| 용도 | 새 카드를 기존 그룹에 배정 / JD 매칭 | 조치와 결과를 인과로 묶기 |
| 비용 | 0원 (로컬 가능) | 호출당 수 원 |
| 중요도 | 보조 | **핵심** |

### 왜 임베딩만으로는 부족한가

```
02.14  "결제 API 느려서 레디스 캐시 붙임"
03.02  "지난달 캐싱 작업 이후로 지표 좋아짐"
```

**어휘가 하나도 안 겹친다.** 유사도가 낮게 나와 다른 묶음으로 가버린다.
그런데 이 둘을 붙이는 것이 정확히 이 제품이 존재하는 이유다.

조치와 결과는 원래 비슷하게 생기지 않았다. 하나는 무엇을 했는지,
다른 하나는 무엇이 변했는지를 말하기 때문이다. **이건 인과 추론이고 LLM의 일이다.**

## 6. 비용 구조

| 작업 | 실행 위치 | 건당 비용 | 빈도 |
|---|---|---|---|
| 카드 → 그룹 배정 | 로컬 임베딩 | 0원 | 매 입력 |
| 메모 → 경력 문장 | API | ~0.5원 | 하루 1회 |
| 카드 묶음 → STAR | API | ~30원 | 가끔 |

유저 1명당 월 수십 원. **로컬 LLM으로 옮겨 아끼는 금액이 서버비보다 작다.**

다만 "운영 시에는 분류를 로컬 임베딩으로 내려 비용을 0으로 만든다"는 설계는
발표에서 언급할 가치가 있다. 비용 구조를 생각해본 팀으로 읽힌다.

## 7. 차트 라이브러리

**Recharts.** 기존의 Plotly/Altair 결정은 "Streamlit 네이티브 통합"이 이유였으므로
Streamlit을 걷어낸 지금 근거가 사라졌다. React 환경에서는 Recharts가 자연스럽다.

---

## 8. 노션 연동: 읽기 전용

공식 REST API로 읽기만 한다. **쓰기는 구현하지 않는다.**
읽기에서 쓰기로 스코프를 넓히면 OAuth 동의 화면이 무거워지고 유저가 한 번 더 망설인다.
경력기술서 내보내기는 클립보드 복사로 충분하다.
