# 리스크 및 폴백 전략 (2026-09-13 개정)

> **해소된 리스크 2개** — OCI 전환으로 아래 둘은 이 문서에서 삭제됐다.
> - Chroma 퍼시스턴스 유실 (블록 스토리지라 재시작에도 유지)
> - 콜드 스타트 (상주 프로세스)

---

## 리스크 1: 음성 입력이 실기기에서 안 됨 ★ 최우선

**증상**: 데스크탑 크롬에서는 되는데 iPhone Safari에서 마이크 권한이 안 뜨거나 인식이 안 됨.

**왜 치명적인가**: 자차 출퇴근 시나리오가 제품 컨셉의 절반이다. 이게 빠지면
"퇴근 15분 전 타이핑"만 남아 차별성이 크게 줄어든다.

**타임박스**: 9/13(일) 중 검증 완료. **다른 어떤 작업보다 먼저.**

**폴백**:
```
Web Speech API 실패 → MediaRecorder로 녹음 → 서버에서 STT API로 변환
```
실시간 인식은 아니지만 **"말해서 기록한다"는 경험은 동일하다.**
운전 중 시나리오는 어차피 정차 후 한 번 말하는 쪽에 가깝다. 반나절이면 된다.

구현 방식에 집착하다 제품을 잃지 말 것. 심사위원은 어떤 API를 썼는지 모른다.

**주의**: 폴백으로 가면 UX가 "실시간 자막"에서 "녹음 버튼 하나"로 바뀐다.
화면 설계가 달라지므로 디자인에 즉시 공유.

## 리스크 2: 백엔드 P0가 9/15까지 안 끝남 ★ 게이트

**증상**: 저장소 / `build_resume()` / 프로젝트 층 중 하나라도 미완.

**왜 치명적인가**: 이 셋이 없으면 보여줄 제품이 없다.
현재 레포는 "메모 한 줄 → 문장 + 태그 → JD 매칭" 데모일 뿐이고,
시간차 누적이라는 핵심 가치가 구현돼 있지 않다.

**판단 시점**: 9/15(화) 저녁.

**폴백**: **Next.js 전환을 중단하고 Streamlit으로 마감한다.**
화면은 투박해도 제품은 남는다. 반대는 성립하지 않는다.

이 경우 음성 입력은 Streamlit iframe 제약을 그대로 안고 가야 하므로,
`st.audio_input` + STT 방식으로 간다 (리스크 1의 폴백과 동일).

## 리스크 3: OCI 배포가 막힘

**증상**: 접속 자체가 안 되거나, HTTPS 인증서 발급 실패, 서비스워커 등록 실패.

**타임박스**: 9/17(목) 하루. 연습 배포는 9/16 저녁에 미리 1회.

**자주 막히는 지점**
- OCI 보안 목록과 VM 내부 방화벽 중 **한쪽만** 열어둠 (둘 다 열어야 함)
- HTTPS 없이 마이크/푸시 검증 시도 (인증서가 선행 조건)
- 서비스워커가 하위 경로에서 서빙돼 scope가 루트가 아님
- ARM VM에서 `next build` OOM (swap 추가로 해결)

**폴백**: 9/17 저녁까지 안 되면 **로컬 데모로 발표 준비를 전환한다.**
배포 실패보다 나쁜 건 배포를 붙잡다 발표 준비를 못 하는 것이다.
노트북에서 돌리고 화면 공유로 시연해도 심사에 큰 감점은 없다.

## 리스크 4: LLM이 없는 숫자를 지어냄 ★ 제품 신뢰도

**증상**: 유저가 "결제 터진 거 막음"이라고만 썼는데
STAR 결과에 "응답 시간 200ms 단축"이 나옴.

**왜 치명적인가**: 유저가 그 문장을 이력서에 넣고 면접에서 검증당한다.
**제품이 유저를 위험에 빠뜨리는 결함이다.** 데모에서 발견되면 신뢰가 통째로 무너진다.

**대응**:
1. 프롬프트에 명시적 제약 — "기록에 실제로 적힌 숫자만. 없으면 result를 비워라"
2. `source_dates` 반환 강제 — 근거 추적 가능하게
3. **환각 테스트를 CI에 넣는다** — 숫자 없는 입력에 숫자가 나오면 테스트 실패
4. UI에서 빈 `result`는 되묻기 칩으로 처리

## 리스크 5: 한국어 임베딩 품질

**증상**: `chroma_default`(all-MiniLM-L6-v2)는 영어 위주라 한국어 스킬 태그
매칭 품질이 검증되지 않았다. 로컬 `bge-m3`로는 품질이 좋았으나 프로덕션에 없다.

**대응**: OCI VM에 Ollama를 직접 설치할 수 있다. ARM 무료 티어(4 OCPU / 24GB)면
`bge-m3` 임베딩은 충분히 돈다.

**단, P0 완료 후에만 손댈 것.** JD 매칭은 P1이고 임베딩 품질은 그 안의 세부다.

---

## 리스크 6: 노션 멀티유저 토큰 사고

**증상**: `user_token` 없이 호출했는데 `settings.notion_token` 폴백이 동작해
**다른 사용자가 개발자 본인의 노션 데이터를 보게 됨.**

**대응**
- 프로덕션 경로에서 `user_token`을 절대 optional 취급하지 않는다
- `settings.notion_token` 폴백은 로컬 단독 테스트 전용으로 격리
- 모듈 전역 클라이언트 캐싱 금지 (`lru_cache` 패턴 금지)
